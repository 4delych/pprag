# Помощник по документации проекта

Учебный RAG для доклада на 15 минут: Markdown → фрагменты → Ollama embeddings → Qdrant → найденный контекст → Ollama LLM → ответ и источники. Корпус `knowledge/` описывает вымышленный TaskBoard 1.0. Сам TaskBoard не реализован: команды в его документации — данные для помощника. Запуск RAG описан ниже.

## Состав

- Python 3.12; `langchain-text-splitters` сохраняет заголовки и делит длинные разделы.
- `ollama`: официальный Python-клиент; `bge-m3` для многоязычных embeddings и `qwen2.5:3b` для ответа. Это выбранные учебные модели, а не утверждение об их превосходстве.
- `qdrant-client`: хранение векторов и метаданных, поиск по косинусному сходству, переключение снимков через alias.
- FastAPI: `POST /ask`, интерактивное описание API `/docs`.
- AnythingLLM: отдельный готовый вариант из того же Compose, с собственным индексом.

## Подготовка на Windows PowerShell

Нужен запущенный Docker Desktop с Linux containers. В папке проекта:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
docker compose up -d qdrant ollama
docker compose exec ollama ollama pull bge-m3
docker compose exec ollama ollama pull qwen2.5:3b
.\.venv\Scripts\python.exe -m rag_demo index knowledge
.\.venv\Scripts\python.exe -m rag_demo ask "Как настроить и запустить TaskBoard?"
.\.venv\Scripts\python.exe -m rag_demo search "Как сменить порт на 8080?"
.\.venv\Scripts\python.exe -m uvicorn rag_demo.api:app --host 127.0.0.1 --port 8000
```

В соседнем терминале:

```powershell
$requestBody = @{question="Как настроить и запустить TaskBoard?"} | ConvertTo-Json
Invoke-RestMethod -Uri http://127.0.0.1:8000/ask -Method Post -ContentType 'application/json; charset=utf-8' -Body ([System.Text.Encoding]::UTF8.GetBytes($requestBody)) | ConvertTo-Json -Depth 8
```

Qdrant: `http://localhost:6333/dashboard`. FastAPI: `http://localhost:8000/docs`. Порты контейнеров привязаны к loopback. Приложение рассчитано на локального пользователя; перед сетевой публикацией нужны аутентификация и фильтрация документов по правам пользователя ДО формирования контекста.

Compose использует CPU для переносимости. Генерация может занимать существенное время. GPU настраивается отдельно под конкретное оборудование. Скачанный размер модели не равен требуемой оперативной памяти: кроме весов нужны память для контекста, embedding-модели, Qdrant и ОС. Для полностью повторяемой сборки зафиксируйте digest Docker-образов и моделей; теги `latest` подвижны. `requirements.lock.txt` фиксирует Python-окружение проверенного запуска на Windows/Python 3.12.

## Вариант без Docker для Qdrant

Установите Ollama отдельно, скачайте те же модели командами `ollama pull ...`, задайте `QDRANT_PATH=.local-qdrant` в `.env`. Python-клиент Qdrant сохранит базу в этой папке. Индексация и API должны запускаться последовательно: встроенный режим блокирует каталог для одного процесса. Для параллельной работы используйте сервер Qdrant.

## Обновление базы

Измените `knowledge/`, задайте согласованную версию `DOCS_VERSION` и повторите `python -m rag_demo index knowledge`. Новый набор полностью индексируется в отдельную коллекцию. Только после успешной загрузки alias `project_docs` переключается на неё. Удалённые документы не попадают в новый снимок. Старые коллекции намеренно остаются для отката и занимают диск; удаляйте ненужные снимки осознанно через Qdrant. При изменении embedding-модели обязательно переиндексируйте корпус. Даже модели с одинаковой размерностью могут задавать разные векторные пространства.

## Готовый вариант AnythingLLM

```powershell
docker compose --profile ready up -d anythingllm
```

1. Откройте `http://localhost:3001` и выполните первоначальную настройку.
2. В провайдере LLM выберите Ollama, адрес `http://ollama:11434`, модель `qwen2.5:3b`.
3. В провайдере embeddings выберите Ollama с тем же адресом и моделью `bge-m3`. Укажите это до индексации.
4. Оставьте встроенное векторное хранилище AnythingLLM (LanceDB); это отдельная реализация, она не использует коллекцию Python-примера.
5. Создайте workspace `TaskBoard 1.0`, загрузите три файла из `knowledge/` и добавьте их в workspace с индексацией (Embed / Save and Embed). Обычное вложение в чат может передавать текст целиком и не демонстрирует RAG.
6. Для сравнения выберите Query Mode вместо режима агента; задайте инструкцию отвечать только по документам и признавать отсутствие данных. Названия пунктов могут меняться между версиями.
7. Задайте те же вопросы из `evaluation/questions.json`; раскройте источники и сопоставьте факты с документами.

Адрес `http://ollama:11434` работает внутри сети этого Compose. Если Ollama запущена на хосте Windows, а AnythingLLM — в контейнере, используйте `http://host.docker.internal:11434`. Для AnythingLLM Desktop и Ollama на одном хосте — `http://localhost:11434`.

## Проверка качества

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe scripts/evaluate.py
```

`pytest` проверяет реальный embedded Qdrant, разбиение, обновление базы, цитаты и API с явной подменой моделей. Он НЕ измеряет качество нейросетей. `evaluate.py` вызывает настоящую настроенную Ollama, сохраняет ответы, найденные фрагменты, наличие ожидаемого раздела в top-k и текстовые признаки ответа в `artifacts/runs/`. Это небольшой набор из 6 вопросов, а не статистическая оценка. Отдельно вручную проверьте, подтверждает ли каждый источник каждое утверждение; наличие `[1]` не является доказательством.

Порог `SCORE_THRESHOLD=0.35` — стартовая настройка, а не вероятность правильности. Отсутствие фрагментов даёт отказ без генерации. Если найденные фрагменты не содержат ответа, отказ зависит от поведения модели и не гарантирован. Статус `citation_warning` означает отсутствующие или недопустимые номера ссылок; `generated` также не гарантирует правильности. Поле `sources` содержит все найденные фрагменты, `citations` — распознанные номера ссылок из текста ответа.

## Ограничения примера

Только UTF-8 Markdown, один корпус и один пользователь. Нет OCR/PDF-парсинга, ACL, гибридного поиска, reranker и промышленного мониторинга. Инструкция в system prompt снижает риск выполнения команд из документов, но не является полной защитой от prompt injection. Документы не выполняются как код. Внешний API в данной реализации не подключён; для него нужно заменить адаптер `OllamaModels` и отдельно настроить передачу данных и ключи. Провайдер embeddings и провайдер генерации выбираются независимо.

## Материалы выступления

Полный текст, подписи и порядок слайдов находятся в `artifacts/report.md`. Изображения листингов в `artifacts/code/` получены из указанных строк реальных файлов, а не из отдельно набранного псевдокода. Они предназначены для слайдов и Google Документа. Сценарий не требует живого запуска.

Для повторной сборки изображений на Windows установите `requirements-materials.txt`, выполните `python scripts/render_code.py`, `python scripts/render_diagrams.py`, затем `python scripts/build_report_html.py`. В `artifacts/report.html` находится локальная копия с оформлением и встроенными изображениями.

В Git хранится исходный текст доклада `artifacts/report.md`. Изображения, HTML-копии и временные файлы проверки генерируются локально и исключены из репозитория.
